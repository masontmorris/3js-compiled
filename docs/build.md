# Build the Windows host

Install Rust 1.99.1, MSVC Build Tools with the Windows SDK and the C++ ATL component, CMake, LLVM, and NASM. Static DXC links against ATL. The SDL3 bindings build and link SDL3 from source. The build does not need an SDL installation.

Load `vcvars64.bat` into the shell environment. Add the Cargo, LLVM `bin`, and NASM directories to `PATH`. Set `LIBCLANG_PATH` to LLVM's `bin` directory. Set `CARGO_TARGET_DIR` to `C:\3jsc\target` and clear `CARGO_BUILD_BUILD_DIR`. Set `CARGO_PROFILE_DEV_DEBUG=0` and `CARGO_PROFILE_RELEASE_DEBUG=0` to reduce build size.

```powershell
cargo build -p threejsc-host
```

Run `host --entry examples/clear.js` to open a window that changes color on each animation frame. Close the window to exit. On the shared Windows machine, use the GPU lease in [testing](testing.md).

The host and Servo use separate Cargo workspaces because their JavaScript engines require incompatible ICU versions. Build both before running a HUD example:

```powershell
cargo build --release --locked -p threejsc-host
cargo build --release --locked --manifest-path crates/ui-host/Cargo.toml
```

Copy ANGLE's DLLs next to `ui-host.exe`:

```powershell
$angle = Get-ChildItem "$env:CARGO_TARGET_DIR/release/build/mozangle-*/out/libEGL.dll" | Sort-Object LastWriteTime -Descending | Select-Object -First 1
Copy-Item "$($angle.DirectoryName)/libEGL.dll", "$($angle.DirectoryName)/libGLESv2.dll" "$env:CARGO_TARGET_DIR/release/"
```

Run `host --entry examples/hud/game.js` from the repository root. Use `--no-ui` to run the game without starting Servo. The game calls `bridge.open(path)` once to select its page, during module load or after a top-level `await`, and the host starts the UI at the end of the frame that sees the call. `bridge.send(patch)` merges a patch into the UI state and sends the whole state. It throws a `RangeError` and keeps the previous state when the state's JSON exceeds 1,048,555 bytes. `bridge.onEvent(fn)` subscribes to page events.

The page implements `window.__bridge.tick(state)` and returns a JSON string with `events` and `rects`. Each rectangle is `[x, y, width, height]` in window pixels. ui-host calls `tick` at most once per Servo frame, always with the newest state. It also calls `tick` with the current state after pointer input and after 100 ms without a call, so page events reach the game when the game sends no new state. It makes no call before the game's first `bridge.send`.

Pointer input goes by the HUD frame on screen. The host hit-tests each pointer event against the rectangles the page listed at the size of the shown frame. For a few frames after a resize, the host still shows the last frame at the old size while Servo lays the page out at the new size. During a continuous resize, ui-host applies the newest size only once the page has been laid out at the previous one, that frame is published, and the host has shown it or 100 ms have passed, so the HUD shows a recent size at least every 250 ms. The host shows frames of ui-host's newest ring only, and its `UI ring N (WxH) replaced by ring M before its published frame was shown` note in `host.log` names a ring that never reached the screen. A pointer event on a rectangle drawn in that frame goes to the page. A pointer event where the shown frame draws no rectangle goes to the game at once. A press, from a button down to the last button up, goes entirely to the side its down went to, as with a browser's implicit pointer capture. The game never receives part of a press on a drawn HUD element, and the page never receives part of a press that began on the game. The host sends each page event to ui-host with the rectangle it was made over: the rectangle's element ids and the event's offset from its corner in the frame on screen. During a page press, an event over no rectangle goes with its offset from the corner where the frame then on screen drew the rectangle that the press's down was over. ui-host places each event when it gives it to Servo. An event the host hit-tested in a frame laid out at the size Servo lays the page out at keeps its window point, as in a browser. An event hit-tested in a frame at another size is placed on the rectangles of the page's latest reply at Servo's size. The event goes to the same offset from the rectangle that names the same element, or to that rectangle's centre when it has shrunk past an event made over it (the next paragraph says which rectangle). An event none of whose element ids the latest layout has keeps its window point. Every point is clamped into the page's viewport, because Servo drops input outside it. While a resize waits for the page's layout at the new size, ui-host holds page input in order. It applies no resize while Servo has page input it has not yet handled, so Servo hit-tests each event in the layout it was placed in. A reply that leaves out `rects` keeps the rectangles the page listed last. If the page reports no layout at the new size within 200 ms, ui-host places the held input on the rectangles the page listed last and counts it in its `pointer events placed without the page's layout at its size` log line.

A game therefore gets, at once and at its window point, every pointer event that is not the page's. A page gets every event of a press that began on a drawn element. An event over a drawn element reaches that element, at the same point of it in the page's current layout, even while the frame on screen is laid out at an older size. ui-host's vendored `servo-script` fires `click` as Chrome and Firefox do, on the nearest common ancestor of the elements the press's down and up were over, however far apart the two points are (`crates/ui-host/vendor/README.md`). A press whose down and up are both on one element clicks that element, even when a resize moved the element between them. A press released over another element clicks the common ancestor of the two, such as `body`, and one released over no element clicks `html`. A middle or right button's press fires `auxclick` there in place of `click`, and a right button's up then fires `contextmenu` on the element under it, as in Edge on Windows. As in Edge, each button up ends the press of the latest button down, whichever buttons they are, so a left press with a right click inside it fires the right click's `auxclick` and no `click`. A disabled form control receives pointer events, `mousemove` and `mouseover`, and no `mousedown`, `mouseup` or `contextmenu`. A press that begins or ends on one clicks the common ancestor, unless that is the disabled control itself, which gets no `click` or `auxclick`. Page input made during a resize reaches the page once it has laid out at the new size, a few frames later than usual.

Each rectangle must be the border box of an element of the page, as `getBoundingClientRect` gives it, to within 1 px, when `tick` returns. ui-host gives every element its own id for as long as the element stays in the page, and no id passes to another element. A rectangle names one element whose box it is: the topmost one that takes clicks, which ui-host takes to be the last in document order whose `pointer-events` is not `none` (for siblings, the one drawn on top, below), or the topmost one when none of them takes clicks. It also carries up to three more ids, of the other elements with that box that take clicks, topmost first. So a rectangle around a button whose label fills it names the label and carries the button's id, a button that fills its column at one width is named at every width, and a focus ring with `pointer-events: none` never gets an id while a button shares its box. Of two siblings with one box ui-host names the one Servo's hit test at the rectangle's centre draws on top, so `z-index` counts, or the later in document order when the hit test there reaches neither. Either way the ids only find the rectangle in the page's latest reply: Servo's hit test at the placed point decides which element an event reaches, as Edge's does. Rectangles that share one box name its elements from the bottom up. The page lists no ids of its own, and may add, remove and reorder its `rects` between any two replies. An event made over a rectangle in a frame at an old size goes to the rectangle of the latest reply that names the element the old one named, else to the first that carries that element's id, else the same for each of the old rectangle's more ids in turn. So a click on a button whose label the page rebuilds every tick still finds the button. An event over a rectangle with id 0, or over one whose elements the page has all replaced, keeps its window point. ui-host looks for a rectangle's elements among those the page measured with that box during `tick`, else among those the same box, then the rectangle at the same place in the list, named in the last reply, else by a document scan. With each element found it checks the element's ancestors, descendants and next siblings for the same box. ui-host's work after `tick` stops 2 ms into the evaluation, box reads and the document walk included. A computed rectangle not checked by then has id 0 and is checked first in the next evaluation. Rectangles the page measured cost no box reads to check. The document scan takes at most 1 ms of that, going on in the next evaluation until it has seen every element once, so in a page of thousands of elements a computed rectangle can take a few evaluations to get its id, and has id 0 meanwhile. In every other evaluation, box reads of elements whose `offsetWidth` the page read during `tick` stop 1 ms in, so however many the page reads, rectangle checks and the scan get the rest of the 2 ms. A rectangle that a whole scan finds no element for is not looked for again for 60 evaluations. ui-host's caches hold only the boxes of the page's latest reply. ui-host writes the index of the first rectangle that a whole scan found no element for to `ui-host.log` and `host.log`, once per process, and counts such rectangles in its `rects that outline no element of the page` line. A rectangle still being looked for is not counted.

The game receives at most 256 page events per frame, in one call. When more than 4,096 events wait, the host drops the newest and listeners receive `{ type: "bridge:dropped", count }`. The host writes each rejected reply or reply item to `host.log`.
